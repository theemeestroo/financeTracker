## Layout & provider chain

- **`app/layout.tsx`** (root) — loads `Host_Grotesk` (`--font-sans`) and `Geist_Mono` (`--font-geist-mono`) via `next/font/google`, sets metadata, wraps `{children}` and a single global `<Toaster />` in `next-themes`' `<ThemeProvider attribute="class" defaultTheme="dark" enableSystem={false}>` (`<html>` carries `suppressHydrationWarning` for it). No auth logic, no data fetching.
- **`app/(app)/layout.tsx`** (route group layout) — Server Component. Creates a Supabase server client, calls `supabase.auth.getUser()`; redirects to `/login` if unauthenticated (a page-level auth check *in addition to* the request-level proxy gate — see `docs/auth-and-security.md`). If authenticated, renders `<AppSidebar userEmail={user.email}>` plus a `<main>` panel (`rounded-[2rem] bg-content-panel`) wrapping `{children}` in a scrollable padded container.

`/login` and the root `error.tsx` sit outside `(app)/layout.tsx` — no sidebar shell.

- `checklist-item-checkbox.tsx` — client; checkbox that auto-submits a bound server action on change (severance-scenario checklist toggling).

- `currency-amount.tsx` — server; renders a EUR-first amount with the as-entered currency shown underneath when non-EUR.
- `delete-button.tsx` — client; wraps a `<form action>` bound to a delete server action with a confirm dialog before submit.
- `override-popover.tsx` — client; small `Popover`-wrapped single-field `useActionState` form for setting a global event/savings-rule/property-change's per-scenario override value — shared by the scenario page's merged Timeline/Savings & Investment tables (see `/severance-scenarios/[id]` above). `field`/`type` props pick the input name and `number`/`date` kind so the same component serves both a numeric override and a property change's date override.

**`components/charts/*.tsx` — chart widgets** (Recharts-based except `surplus-tile.tsx` and `tax-bracket-bar.tsx`, both plain server components; all Recharts ones are client)
- `category-breakdown-chart.tsx` — bar chart of commitment spend by category (dashboard); hovering a bar lists the individual commitments behind that category's total.
- `comparison-chart.tsx` — multi-series line chart comparing several scenarios' runway projections (`/severance-scenarios/compare`); an optional per-series `dashed` flag renders the do-nothing baseline (DESIGN v2 §2.5) as a muted dashed reference line instead of another scenario.
- `depletion-chart.tsx` — composed area/bar chart of one scenario's balance over time; supports a click-to-select month (see `runway-projection.tsx`), a highlighted current-period column, and an optional `baselineSeries` prop overlaying the do-nothing reference line (dashed, `--muted-foreground`). Optional `memberById`/`perMember` props (both omittable — the plain dashboard usage at `/` passes neither) add, once `memberById` has 2+ entries: per-person balance lines in the hover tooltip, and a small `ReferenceDot` per person's own depletion date (`--series-2`/`--series-3`/`--series-4`/`--series-1` cycling by roster order, deliberately skipping `--series-1` first since it's the same hex as `--status-good`) alongside the household total's own larger `--status-critical` dot.
- `runway-projection.tsx` — wraps `DepletionChart` plus a per-month itemized income/outgoings breakdown panel (segmented bar + line items) for the selected month; passes through `baselineSeries` and adds its legend entry. Each income line item shows its net figure plus, when the item's `grossAmount` genuinely differs from `amount`, a muted "gross" sub-line — omitted for a no-tax-profile-yet gross fallback or a tax-exempt item (ALG I, tagged "(tax-free)" instead) since those would just repeat the same number twice. Requires a `memberById: Map<id, name>` prop (the household roster); once it has 2+ entries, also renders the Runway-status pill row, groups each breakdown column by person + "Shared" (`groupByAttribution`, keyed off `RunwayLineItem.householdMemberId`), and adds the per-person balance line — all three gated on the same 2+ check, and all no-ops (identical to the pre-per-person UI) for a single-member household.
- `surplus-tile.tsx` — server; stat tile showing monthly income − commitments with an up/down status indicator (dashboard).
- `tax-bracket-bar.tsx` — server; a full tax-bracket *ladder* (plain divs, no Recharts), not just the filled portion — every one of a `taxBracketBreakdown` result's five §32a zones gets its own always-visible column (rate label, mini fill-track, euro range), so the whole 0–45% structure is shown regardless of how much of it a person's income actually reaches. Each column's fill is the fraction of *that zone's own* euro range the income has used (the open-ended 45% zone just lights up fully once reached, since there's no natural width to show a fraction of). A 6th column for a severance lump sum taxed via the Fünftelregelung sits after the five, visually distinct (pink `--series-3` vs. the sequential single-hue `--primary` ramp light→dark on the five real zones — a bracket ladder is a magnitude scale, not a set of unrelated categories) since it isn't a literal marginal step. Reached columns are bold/lit; unreached ones stay muted. A legend (dot + label + amount + tax) below lists only the reached columns. Used on the severance scenario page's Tax tab.
- `income-summary-tile.tsx` — server; net monthly income total + a by-IncomeType segmented bar/dot legend (fixed categorical hue order — `--series-1..4`) + a by-person line, shown only when 2+ people actually have income (dashboard, alongside `SurplusTile`). Not owner-filter-scoped — always whole-household, unlike the category breakdown below it.

## Client vs. Server component split

- **Pages (`page.tsx`) are Server Components** almost everywhere — they call `createClient()` from `lib/supabase/server.ts`, run Supabase queries directly in the component body (often `Promise.all`-batched), and pass server-action references (e.g. `updateIncome.bind(null, id)`) straight into client form components as the `action` prop. `notFound()` handles missing single-record lookups.
- **Forms are separate `"use client"` files** (`commitment-form.tsx`, `income-form.tsx`, `household-member-form.tsx`, `tax-profile-form.tsx`, `property-form.tsx`, `package-form.tsx`, `phase-form.tsx`, `event-form.tsx`, `property-end-form.tsx`, `checklist-item-form.tsx`, `variant-generator-form.tsx`, `savings-rule-form.tsx`, `new-profile-form.tsx`, and similar) — they hold local state/validation and call the server action passed in as a prop, keeping the parent page itself server-rendered.
- **Small interactive widgets are isolated client components**: `DeleteButton`, `ChecklistItemCheckbox`, `CollapsibleTableGroup`, the dashboard's owner filter, the properties page's property switcher, the compare page's scenario picker, and every chart component (Recharts requires the client).
- **Presentational-only leaf components stay server** where no interactivity is needed: `CurrencyAmount`, `SurplusTile`, `IncomeSummaryTile`.
- Design-system primitives in `components/ui/` are client wherever they wrap an interactive `@base-ui/react` primitive (dialog, popover, select, sheet, tabs, tooltip, calendar, date-picker, checkbox) and unmarked/server where purely presentational (badge, card, skeleton).

When adding a new page, follow the existing pattern: keep the `page.tsx` a Server Component, put any form in its own `"use client"` file bound to a server action, and only reach for a client wrapper around the whole page if the page needs shared interactive state across multiple sections (see `components/charts/runway-projection.tsx` for that pattern).
